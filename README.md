# marketplace_gluing

Сборка склеек карточек для WB и Озона (Профтекс, Milky Garden, Timeless).
Отдельно от `marketplace_db_sync`: тот собирает базу, этот только читает из неё и считает.
Применяют склейки существующие скрипты `wb_skleyki.py` и `ozon_skleyki.py` по листу «Склейки».

## Состояние

Готово: профиль **WB Профтекс** (жадный сборщик и CP-SAT) и **Озон** (дерево разбиений, все кабинеты).
Дальше: чтение из базы напрямую, проверка бренда Озона через API, WB в той же логике дерева, прогноз спроса.

## Как устроено

```
gluing/
  model.py     Card, Group
  parsing.py   артикул -> префикс, дизайн, ключ
  brands.py    бренд по префиксу (PT, PC, MT, AM, PA, MY, ... , без префикса = Timeless)
  cards.py     единая таблица карточек: остатки WB РФ + FBS + отрезы из рулонов, заказы
  rules.py     правила -> корзины (порядок задаёт профиль)
  builder.py   корзины -> деление поровну -> объединение мелких соседних ключей
  checks.py    жёсткие нарушения и сомнительные места
  report.py    Excel: Склейки, Контроль, Баланс хит-неликвид, Реестр рулонов, Расчет тканей, Проверка малых
  data/        eco_designs.csv, child_designs.csv (списки, которые ведут коллеги)
profiles/      настройки «площадка + кабинет» (TOML)
tools/         compare_with_file.py — сверка с готовым файлом склеек
tests/         pytest
fixtures/      снимок данных с сервера для разработки (не в git)
```

## Запуск

```
python build.py profiles/wb_proftex.toml --out output/wb_proftex.xlsx
python tools/compare_with_file.py profiles/wb_proftex.toml "<готовый файл>.xlsx"
python -m pytest -q tests
```

Пока данные берутся из CSV в `fixtures/` (выгрузка из `marketplace_sync`). Загрузчик из базы — следующий шаг.

## Правила (ядро)

- Жёстко: один бренд и одна категория в склейке, не больше `max_group` SKU, каждая карточка ровно в одной склейке.
- Активная карточка WB: остаток «Склад WB РФ» + FBS (Селсап) + отрезы из рулонов > 0.
- Рулоны: склад FBS Селсапа, артикул `PTxxxx`, метры; отрез L м = остаток // L, только категория «Ткани для рукоделия».
- Порядок правил: карнавал, декоративные наволочки, бренд «вся категория вместе» (Сказка Сатин, Анна Мария),
  0-0-263, KANT, ромбы, эко-рюши, эко, рюши, детские, ключ.
- Мелкие ключи одной категории и бренда склеиваются соседями, пока влезает в лимит; отель 0-0-260 идёт к 0-0-26.
- Бренд определяется только по префиксу; неизвестный префикс не склеивается молча.

Сверка с файлом GPT за 05.10: тип правила совпал у 98% карточек; оставшееся — обновлённый детский список,
эко-карточки с малым остатком и правило 0-0-263 «независимо от эко».


## Озон (gluing/ozon, profiles/ozon.toml, build_ozon.py)

Единица склейки — дизайн (дизайн не делится). Дерево: бренд (по префиксу) → тип товара (жёстко: Озон склеивает
только один тип и бренд) → признак типа → детские → эко → размер 6–18 дизайнов.

- Признак дизайна: любой SKU с редким признаком (рюши, ромбы, кант, пуговицы...) тянет весь дизайн в свою ветку.
  Простыни по резинке не делятся: резинка и классика — варианты одного дизайна.
- Признак, детские, эко отделяются при ≥ 10 дизайнах, сливаются обратно только при < 8 (гистерезис).
  Мало — остаётся в родителе по цепочке запасных веток (кружево → рюши → обычные, кант → обычные...).
- Ветка больше 18 дизайнов делится на равные части; дизайны «липнут» к вчерашней группе (состояние в JSON).
- Узел бренд × тип меньше 6 дизайнов: «малая склейка» из 2–5 дизайнов; 1 дизайн — «одиночка», не склеить.
- Бренд неизвестного префикса не склеивается, а выводится на отдельный лист.

```
python build_ozon.py profiles/ozon.toml --cur fixtures/g_ozon.csv --out output/ozon.xlsx --state-out output/state/ozon.json
python build_ozon.py profiles/ozon.toml --cur fixtures/g_ozon.csv --prev-csv fixtures/g_ozon_prev.csv   # проверка стабильности
```

Результат на данных 07.10 (1 331 дизайн): 88 склеек, 8 малых, 2 одиночки; за сутки склейку меняют 1,8% дизайнов
(при делении веером по рангу было 50%).
