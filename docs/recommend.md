# Рекомендации продавца на WB

Правила: `по рекомендациям правила.xlsx` (слоты на карточку из 20 артикулов), реализация `recommend/wb.py`, настройки слотов `[recommend]` в `profiles/wb_*.toml`.

## Как работает ежедневная загрузка

`python -m tools.wb_recommend --jam` (оркестратор proftex-server, сервис `gluing-wb-recommend`, 07:40 МСК, после применения склеек):
1. Считает рекомендации по трём кабинетам (карточки с остатком, хиты/неликвиды по заказам за 30 дней, новинки по nmID, ротация).
2. Сверяет с текущими на WB (`/api/content/v1/recommendations/list`, ключ чтения) и оставляет только изменившиеся карточки.
3. Грузит файлы по шаблону Джема (`recommend/wb_template.xlsx`, до 1000 строк, режим «Заменить») через Chrome кабинета (CDP, порты в `cdp_port`
   профиля: skazka 9222, milky_garden 9223, timeless 9224 — те же браузеры, что у автоответов на отзывы). Запросы идут из самой страницы
   seller.wildberries.ru (`recommend/wb_jam.py`): токен сессии остаётся в браузере.
4. Через 2 минуты перепроверяет по `/list`. Код возврата 1 и подробности в `logs\wb_recommend.log`, если нет браузера, нет входа в WB, WB не принял файлы.

Нужно: в Chrome каждого кабинета один раз войти в seller.wildberries.ru (вкладка может быть любой, код возьмёт любую вкладку seller.wildberries.ru
или откроет и закроет свою). Подбор заголовков авторизации (AuthorizeV3, Seller-Lk) делает страничный скрипт пробой безопасным запросом истории,
удачный вариант запоминается в `state/wb_jam_auth.json` (только названия источников).

## Официальный API

`--apply` пишет через `/api/content/v1/recommendations/set` (до 5000 карточек за запрос), но метод доступен только с тарифом «Продвинутый/Премиальный»
в подписке Джем или с опцией «Блок “Продавец рекомендует”»; иначе 403 «token does not satisfy additional requirements». Когда опция появится,
`--apply` заменит браузерную загрузку (токен: `WB_REC_TOKEN_SK/MG/TL` или токен склеек). Откат: `--restore <кабинет>_backup.json --accounts <кабинет>`.

## Ограничения Джема

- В файле не больше 1000 строк (49 карточек по 20), имя `template (N).xlsx`, лист `Sheet1`, шапка «Артикул WB» / «Связанный артикул WB».
- Карточки, которых нет в `/list`, загрузка не принимает; они пропускаются.

## Отчёт и дашборд

После каждого запуска `--jam` по кабинету уходит сообщение в дашборд Ops Monitor (источник «рекомендации WB») и пишется `out/recommend/report_<кабинет>.xlsx`
(лист «Итог» и лист «Замечания» с конкретными карточками). Проверяется фактическое состояние на WB (`/list` после загрузки), не расчёт:
- у каждой карточки с остатком есть рекомендации (неполные, меньше 20, только считаются);
- в рекомендациях нет артикулов без остатка;
- правила: не на себя, не из своей склейки, без дублей, бренд / эко / группа категорий как при подборе.

Отчёт появляется только если рекомендации заполнились (загрузка прошла, на WB совпало не меньше половины загруженного). Файл прежнего отчёта кабинета удаляется в начале
каждого запуска, а при неудаче в дашборд уходит ошибка «не заполнены» с причиной: устаревшего отчёта по прошлому запуску не бывает.
