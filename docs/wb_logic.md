# Логика склеек WB (Профтекс, пример: «Постельное белье», бренд «Сказка»)

Отличия WB от Озона: карточка WB = дизайн + один размер; склейка (imtID) — до 30 карточек; двухуровневой склейки нет,
поэтому в одной склейке **один размер у разных дизайнов**. Озон: дизайн целиком (все размеры) и 6–18 дизайнов в группе.

Шаги (ops/wb/wb_plan_all.py):
1. Карточки предмета и бренда из content-api; остатки: «Склад WB» (seller-analytics stocks-report) + FBS/DBS (marketplace-api /api/v3/stocks).
   В план идут карточки с остатком больше 0 (правило проекта для WB).
2. Ветка по правилам проекта в порядке профиля: KANT → эко-рюши → эко → рюши → детские → обычные (ключ).
3. Внутри ветки делим по размеру: ключ артикула (например 4-13-26).
4. Размер режем на части не больше 30 карточек, поровну: 51 → 26 + 25.
5. Если в ветке для размера меньше 6 карточек, они уходят по запасной цепочке: эко-рюши → рюши → обычные того же ключа.
6. Липкость: часть наследует imtID, где уже лежит больше всего её карточек; остаются на месте те, кто влезает в часть.
7. Малые группы (меньше 6) остаются как «малая» и идут на лист проверки: смешивать размеры нельзя.
Выход: wb_plan_all.csv (по карточкам: куда и что делать), wb_groups_all.csv (по группам); для Milky/Timeless с суффиксом кабинета. Записи на WB нет.
