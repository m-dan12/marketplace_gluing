# Применяющий скрипт Озона (`apply_ozon.py`)

Жизненный цикл плана: `draft` → `approved` → `applying` → `applied` | `partial` | `failed` → при необходимости `reverted`.

| Команда | Что делает | Пишет на Озон |
|---|---|---|
| `python apply_ozon.py` | dry-run: разница с живым состоянием, проверки, блокировки | нет |
| `--refresh --env <.env>` | перечитывает атрибуты карточек | нет (только чтение) |
| `--approve --by <имя>` | согласует черновик, пишет в аудит | нет |
| `--execute --confirm <run_id> --env <.env>` | применяет операции | **да** |
| `--rollback <run_id> --execute --confirm <run_id>` | возвращает прежние значения по журналу | **да** |

Запись возможна только при статусе `approved`, с `--execute` и повтором `run_id` в `--confirm`.

## Как применяется
1. Правки «Названия цвета» (атрибут 10097) раньше названий моделей (9048): сначала убираем близнецов.
2. Проба: одна операция; пока она не применилась и не сверилась, остальные не идут (устаревшая проба пропускается).
3. Пакеты по 100. Перед записью значение перечитывается: если оно уже не равно «было» из плана, артикул пропускается.
4. Ожидание статуса задачи Озона, пауза, повторное чтение значения (сверка). Расхождение → `failed`.
5. Каждая операция в `gluing.op` со статусом `done|failed|skipped|reverted` и «было → стало».
6. Предохранитель `--max-ops` (1500): больше операций за запуск не применяется.

## Правки цвета для близнецов
Хвост берётся из атрибута, которым дизайн отличается от первого (не вариативный и не служебный, до 30 символов):
«Бисер, на пуговицах». Если такого нет, порядковый номер: «Бисер 2». Первый дизайн кластера сохраняет имя.

## Ключи
Только из `.env`, путь в `--env` или `MARKETPLACE_ENV`. В репозитории нет ни ключей, ни путей к ним.
Старые скрипты `ops/` остаются как есть и будут удалены после проверки нового применяющего скрипта.

## Остаток и «разлепить»
- В плане артикул держится, пока остаток не меньше `min_total` или с обнуления прошло не больше `[stock] grace_days` (3) дня.
- Артикул вне плана (остаток ниже порога дольше льготного периода), который всё ещё носит имя модели из плана, снимается
  операцией `unglue_model`: «Название модели» = собственный артикул (так выглядит несклеенная карточка на Озоне).
- Если остаток вернулся в льготный период, артикул остаётся в группе без операций. После льготного периода и повторного
  появления остатка он склеивается заново как новый.
